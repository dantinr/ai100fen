# AI100分产品核心方法论

> 状态：Accepted（D-042，2026-10-02）。后续产品设计遵循本方法论。

## 适用范围与规则关系

本方法论指导网站结构、页面流程、课程与课时设计、课程路径、问题池及Z引导。设计须明确用户目标、真实结果、阶段小目标、动作与验证方式，以及人与Agent各自负责的工作。

课程分类、命名、成果与完成标准以[课程宪章](COURSE_CONSTITUTION.md)为最高规则；[PRODUCT.md](../PRODUCT.md)定义产品范围，[MVP.md](../MVP.md)和[DECISIONS.md](../DECISIONS.md)中的最新已接受决策界定当前交付。下文的Z完整职责与产品最终形态是演进方向，需要分阶段落实。

## 文档目的

本文档用于指导 Codex 理解 AI100分
项目的核心理念、网站结构、课程设计和人与 Agent 的协作模型。

AI100分不是传统 AI 教程网站。

核心目标：

> 让用户通过 Agent，把一个想法变成一个真实结果。

------------------------------------------------------------------------

# 一、网站三大核心方向

AI100分围绕三个核心场景：

    AI100分

    Solve       Create       Explore

    解决问题    创作作品     探索可能

------------------------------------------------------------------------

# 二、Solve：解决一个问题

## 定义

从现实中的问题出发，通过人与 Agent 协作，完成一个可验证的解决方案。

流程：

    发现问题

    ↓

    定义问题

    ↓

    分配任务给 Agent

    ↓

    Agent 执行

    ↓

    验证结果

示例：

问题：

每天整理 Excel 消耗大量时间。

目标：

建立自动化处理流程。

最终结果：

一个可以重复使用的自动化方案。

------------------------------------------------------------------------

# 三、Create：创作一个作品

## 定义

从一个想法开始，通过 Agent 协作，完成一个真实作品。

流程：

    提出想法

    ↓

    定义作品目标

    ↓

    拆解任务

    ↓

    Agent协作开发

    ↓

    作品完成

示例：

目标：

制作个人网站。

最终结果：

一个真实可访问的网站。

------------------------------------------------------------------------

# 四、Explore：探索一个可能

## 定义

使用最低成本验证一个想法是否值得继续。

低成本验证是设计目标，不承诺绝对最低成本。完成标准是做过真实实验，并得到明确、可解释、有证据支持的结论；实验失败或证伪也可完成，由人据此判断下一步。

流程：

    提出假设

    ↓

    设计实验

    ↓

    Agent执行

    ↓

    分析结果

    ↓

    决定下一步

示例：

问题：

AI 能否帮助完成某类工作？

通过实验验证：

-   是否可行；
-   成本是多少；
-   是否值得投入。

------------------------------------------------------------------------

# 五、课程设计原则

## 一个课程 = 一个大目标

课程不是知识集合。

每个课程必须回答：

> 学完之后，用户获得什么结果？

示例：

课程：

《100分钟搭建网站》

大目标：

拥有一个公网可访问的网站。

------------------------------------------------------------------------

# 六、课程结构

一个标准课程：

    1个大目标

    ↓

    10节课程

    ↓

    每节10分钟

    ↓

    10个小目标

这是标准产品格式，不是数据库课时数约束。保留D-031已接受的特殊格式：免费实验室的完整小任务为10–15分钟、一个Lesson、验收权重100分；仍须形成可验收的真实结果。

------------------------------------------------------------------------

# 七、单节课程设计原则

每节课必须有：

    一个小目标

    一个明确动作

    一个验证结果

不要设计：

-   第一章 网站基础理论
-   第二章 网站发展历史

应该设计：

例如：

## 第1节

目标：

拥有服务器。

完成：

-   购买服务器；
-   获取IP；
-   登录服务器。

验证：

成功连接服务器。

------------------------------------------------------------------------

## 第2节

目标：

拥有域名。

完成：

-   注册域名；
-   DNS解析。

验证：

域名指向服务器。

------------------------------------------------------------------------

# 八、人的工作模型

AI时代，人的核心价值不是执行。

人的工作：

    发现问题

    ↓

    定义问题

    ↓

    分配任务

    ↓

    检验结果

------------------------------------------------------------------------

## 1. 发现问题

找到真实需求。

例如：

网站访问慢。

------------------------------------------------------------------------

## 2. 定义问题

把模糊问题变成明确目标。

错误：

优化网站。

正确：

首页加载时间从5秒降低到2秒。

------------------------------------------------------------------------

## 3. 分配任务

向 Agent 提供：

-   目标；
-   背景；
-   限制条件；
-   验收标准。

------------------------------------------------------------------------

## 4. 检验结果

人负责最终判断：

-   是否达到目标；
-   是否满足需求；
-   是否产生真实价值。

------------------------------------------------------------------------

# 九、Agent 的工作模型

Agent负责：

## 1. 执行工作

包括：

-   编写代码；
-   查找资料；
-   操作工具；
-   生成文档；
-   测试结果。

------------------------------------------------------------------------

## 2. 总结工作

包括：

-   完成了什么；
-   为什么这样做；
-   遇到什么问题；
-   下一步建议。

------------------------------------------------------------------------

# 十、人和 Agent 的关系

不是：

    人学习工具

而是：

    人提出目标

    ↓

    Agent执行

    ↓

    人验证结果

核心原则：

> 人负责方向，Agent负责执行。

------------------------------------------------------------------------

# 十一、AI100分价值定位

AI100分不是：

-   AI工具大全；
-   Prompt教程；
-   AI新闻资讯。

AI100分解决：

用户知道 Agent 很强，但是不知道：

-   从哪里开始；
-   如何描述目标；
-   如何拆解任务；
-   如何判断结果。

------------------------------------------------------------------------

# 十二、Z 助手定位

Z 是 AI100分 的智能向导。

以下职责描述演进目标。当前Z提供静态引导、关键词免费课程推荐，以及D-041问题池规则对话、可编辑任务卡和登录后确认私人保存；尚未接入真实模型、自动课程路径规划、任务执行或执行结果总结。任务卡保存成功不代表任务已经做成。

职责：

    理解用户目标

    ↓

    帮助定义问题

    ↓

    推荐课程路径

    ↓

    协助执行任务

    ↓

    总结结果

Z不是客服。

Z是用户和 Agent 世界之间的导航者。

------------------------------------------------------------------------

# 十三、产品最终形态

AI100分：

    用户目标

    ↓

    Z

    ↓

    课程路径

    ↓

    Agent执行

    ↓

    真实结果

    ↓

    能力提升

------------------------------------------------------------------------

# 十四、开发要求

Codex开发时需要遵守：

1.  网站所有功能围绕三个核心方向。
2.  所有课程必须有明确目标和结果。
3.  每节课必须有可验证的小目标。
4.  Z必须服务于任务完成，而不是简单聊天。
5.  所有内容设计优先考虑用户最终是否完成一个真实结果。
